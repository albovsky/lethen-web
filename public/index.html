Find dead code in Swift. See why it is dead.

Lethen reads the compiler's index store, so it sees what the compiler sees. Every finding is certain or likely, with the reference chain to prove it.

How it works

A result tells you why

likely means something dynamic, such as Objective-C or a name in a string, could still reach the declaration.

Gate CI on what Lethen is sure about

$ lethen scan --min-confidence certain --strict

Add --write-baseline once, and later scans report only new results.

Ask why something is used or unused

$ lethen explain Store.load

Output as xcode, json, csv, github-actions or gitlab-codequality.

How this was measured

Results with --retain-public, except Wikipedia iOS. Lethen 3.10.0 is master at d7dec6c. Periphery 3.8.0 is upstream tag 3.8.0 (a2db299), the latest upstream release. Both were built from source with swift build -c release. Alamofire, swift-argument-parser, swift-format and swift-nio ran on Linux x86_64 with Swift 6.4 (swift-6.4-RELEASE), at commits bda9ed5, 1021ac8, b15dd59 and feaf4ac, with --retain-public --format json --quiet --disable-update-check. Wikipedia iOS ran at 599e4a6 on an arm64 Mac with Xcode 27.0 (27A266a), Swift 6.4 and macOS 27, with --project Wikipedia.xcodeproj --schemes Wikipedia -- -destination "generic/platform=iOS Simulator".

Findings were matched on file, line, name and hint. For each project, every finding reported by only one tool was listed, and up to 15 per direction were checked by reading the source and, for Lethen, with lethen explain. The raw scan output is not published yet, so treat these numbers as a measurement we made, not a reproducible benchmark.

Not faster: cold scans were roughly equal. Lethen has recall losses of its own, such as unused imports in Objective-C files, and 22 % of Wikipedia iOS findings are only likely. Known issues are on GitHub.

Install

Up and running in two commands

On macOS, Xcode or the Command Line Tools must be installed.

Homebrew (Apple silicon)

$ brew install albovsky/tap/lethen
$ lethen version

macOS zip

Signed and notarized, on every release.

Linux

x86_64 and aarch64 tarballs, glibc 2.35 or later. Steps.

From source

$ git clone https://github.com/albovsky/lethen
$ cd lethen
$ swift build -c release --product lethen

Also the route for Intel Macs.

Then scan

$ lethen scan --project-root /path/to/project

Xcode projects: --project App.xcodeproj --schemes App. Guide.

In GitHub Actions

- uses: albovsky/lethen@<version>
  with:
    baseline: baseline.json

Release 3.10.0 or later. On Linux, use a Swift 6.3+ container such as swift:6.4-noble.
